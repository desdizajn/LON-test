## Gaps to implement in B2

1. **Multi-select with checkboxes** (`selectedIds: string[]`, `onSelectionChange?`, optional `selectable: boolean`).
   - Header checkbox toggles "select all on current page".
   - Indeterminate state when some-but-not-all are selected.
   - Backwards compatible: omitting both props → no checkbox column.

2. **Expandable rows** (`renderExpanded?: (row: T) => ReactNode`, `expandedIds?`, `onExpandedChange?`).
   - When `renderExpanded` is provided, each row gets a leading toggle cell (`▶`/`▼`).
   - Expanded panel renders below the row in a single `TableCell colSpan=...`.
   - Backwards compatible: omitting the prop → no toggle column, no panel.

## Out of scope

- Card-list mobile renderer — current horizontal scroll is acceptable. Reopen in B3 if PageShell's mobile audit flags it.
- Server-side sorting/pagination — current pages are small enough to sort client-side. Reopen in C tasks when paginated APIs land.
- Column visibility toggles — separately useful, not requested by B2.

## Test plan (`components/common/DataTable.test.tsx`)

Per AGENT-PROMPTS §B2:

1. Renders empty state when `data=[]`.
2. Renders one row per data item.
3. Click column header → calls sort; rows re-order.
4. Click "next page" pagination → next slice of rows visible.
5. Click row checkbox → `onSelectionChange` fires with the row id.

All five use `@testing-library/react` (v13.4) + `user-event` (v13.5, fire-event-style API).
